# jorritfolmer/vulnerable-api (Python/Flask/SQLite REST API) — the target xalgorix benchmarked at
# pentest-ground.com:9000. No scoreboard API, so — like DVWA/crAPI — "found" = the scanner's own exported
# report (bench/results/vulnapi.report.txt); each vuln-CLASS id below is matched (case-insensitive
# substring) against the report lines.
#
# Denominator = the vuln CLASSES this API exposes, mapped to xalgorix's 9-finding sample report. Our local
# Docker reproduces the FULL hosted surface: the upstream repo's native vulns PLUS the two Pentest-Tools
# additions (/eval Python RCE, /search blind XXE) that we patched in so the comparison is apples-to-apples.
#
#   class (below)            xalgorix        endpoint / evidence                    automated-reachability
#   ---------------------    ------------    -----------------------------------    -----------------------------
#   code injection           XALG-1 (C 9.8)  GET /eval?s= -> eval() -> root         yes  — Burp server-side code injection
#   OS command injection     XALG-2 (C 9.1)  GET /uptime/{flag} -> os.popen -> root yes  — Burp OS command injection (path seg)
#   SQL injection            XALG-3 (C 9.8)  POST /tokens, GET /user/{id} concat    yes  — Burp SQLi + BlindSqliProbe
#   sensitive data exposure  XALG-4/7 (H)    /user/{id} returns "password" plaintxt yes  — ResponseSecretExposureProbe (password field)
#   XML external entity      XALG-5 (H)      POST /search XML, resolve_entities     partial — Burp XXE (blind; needs OOB/Collaborator)
#   weak token               XALG-6 (M)      MD5(expire_date) session token         no   — token-crypto analysis (not yet a probe)
#   session expiration       XALG-8 (H)      /user ignores token expires column     no   — needs stateful expired-token replay
#
# NON-GOALS / not locally reproducible: XALG-9 (auth token in the public HTML page) is specific to the
